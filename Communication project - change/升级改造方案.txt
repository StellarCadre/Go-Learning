TCP 聊天室升级手册

阶段 v1 TCP核心短板补齐
Day1：TCP 粘包标准解决方案 + bufio 流式读写

一、问题背景
原有 TCP 聊天室直接使用 net.Conn 的 Read/Write 裸方法处理网络数据，存在核心问题：
TCP 粘包：多条消息可能被合并读取（如连续发送两条公聊消息，服务端读取时粘成一条），导致指令解析错误；
固定缓冲区脏数据：用 conn.Read(buf) 读取固定 4096 字节缓冲区，可能读取到不完整消息或缓冲区残留的脏数据；
消息边界模糊：未约定统一的消息结束标志，无法精准分割每条用户指令（如/rename、/to、/list）。
二、升级目标
彻底解决 TCP 粘包问题，保证每条消息完整、独立解析；
改用 bufio 流式读写（按行读取 / 写入），统一以换行符\n作为消息边界；
保持原有业务逻辑（公聊、私聊、改名、在线列表）完全不变，仅优化底层数据读写层。
三、核心技术方案
   优化点	       原有方案                               升级方案
消息边界约定	     无明确约定	            所有消息（客户端发 / 服务端发）均以\n作为结束标志
数据读取方式	 conn.Read(buf) 固定缓冲区	bufio.Reader.ReadString('\n') 按行读取，精准分割每条消息
数据写入方式	 conn.Write() 直接写入	    保持conn.Write()但强制追加\n，确保消息边界统一（可选加bufio.Writer）
四、具体修改步骤
修改点 1：client.go的DealResponseMessage 方法（处理服务端消息）
原有问题：用固定缓冲区conn.Read(buf)读取，易读脏数据、粘包；
修改后：用bufio.Reader按行读取，精准解析每条服务端消息。
客户端发送消息的部分（PublicChat/PrivateChat/Rename）已在发送时追加\n（如sendSeg := fmt.Sprintf("/rename %s\n", client.Name)），符合消息边界约定，无需修改。
修改点 2：Server.go的handleConn 中读取客户端消息的协程。
原有问题：用conn.Read(buf)读取固定缓冲区，易粘包、读不完整；
修改后：用bufio.Reader按行读取，保证每条消息完整。

阶段 1
Day2 TCP 连接精细控制 + DialContext 上下文连接

一、本次升级目标
基于阶段 1（bufio 按行解包）已完成的代码，新增连接超时、上下文控制、心跳保活、精细化网络错误处理，解决现有缺陷：
(1)原有net.Dial无超时，服务未启动时客户端会无限阻塞等待连接:
运行客户端，但没启动服务端：net.Dial("tcp", "127.0.0.1:8000") 会无限阻塞，程序停在这里不动，不会报错退出。
危害:用户不知道是端口错、服务没开，只能强制关掉控制台；程序卡死，无法做友好提示、自动重试逻辑。
本次修复方案:
改用 net.Dialer + DialContext，设置 5 秒超时：
拨号时 ctx 到期直接返回超时错误，客户端打印提示并退出，不会永久阻塞。
(2)仅靠 300s 静态超时，无主动心跳检测，拔网线死连接无法快速识别:
服务端 handleConn 最外层 select { case <-time.After(300s) }
这个定时器只在每次走完一次 select 循环才会重置，有巨大漏洞：
客户端连上后全程不发任何消息，才会 300 秒踢人；
但如果用户中途断网（拔 WiFi、拔网线、电脑休眠），操作系统不会立刻通知程序，TCP 连接会一直挂在服务端，要等 5 分钟才触发超时。
大量僵尸连接占用文件描述符，在线列表堆积无效用户，内存持续上涨。
修复方案
SetReadDeadline：60 秒无任何输入直接超时断开，断网 1 分钟就能识别。
保留 300s 兜底定时器，双重防护。
(3)网络报错仅打印原始 err 字符串，无法区分超时、重置、正常下线:
服务器端原有写法：fmt.Println("连接断开，err:", err)
不管是用户正常输入 0 退出、网线拔掉、超时，打印的都是一串英文原始报错，程序没法区分场景做不同逻辑：
比如正常下线不用打印警告，网络异常需要记录日志告警。线上排查问题无法快速定位故障类型；代码到处重复写错误判断，冗余。
修复方案：
封装统一 PrintNetErr，搭配 errors.Is、errors.As 判断错误种类：
io.EOF：用户正常关闭
context.DeadlineExceeded：操作超时
*net.OpError：网络中断、连接重置
控制台输出分类提示，程序后续也能基于错误类型做逻辑分支。
（4）缺少 TCP 底层保活探测，操作系统层面无法快速回收无效连接。
原理
TCP KeepAlive 是操作系统内核能力：开启后，内核每隔一段时间自动发探测包给对端。
如果多次探测无响应，内核直接标记这条连接失效，通知应用层报错。
你原来 net.Dial 默认关闭 KeepAlive，内核不会主动探测。客户端断网但没正常关闭连接，服务端要等好几分钟才能感知。
修复
net.Dialer{KeepAlive: 30 * time.Second} 开启底层保活探测，内核每 30 秒探测一次，加速死连接回收。

二、本次新增核心知识点
net.Dialer：配置连接超时、TCP KeepAlive 底层保活；
net.DialContext：绑定上下文，拨号过程可主动取消、设置超时；
conn.SetReadDeadline：动态刷新读取截止时间，实现心跳存活判定；
网络错误分层：net.OpError、io.EOF、超时错误，配合errors.Is分类处理；
三、修改文件清单
client.go、Server.go、user.go，新增依赖包：context、errors
四、具体修改步骤
client改造
替换 Dial 为 DialContext，5s 拨号超时 + KeepAlive，新增dialer := &net.Dialer、context.WithTimeout(context.Background(), 5*time.Second)、dialer.DialContext、func PrintNetErr
Server改造
原有仅靠外层 300s 定时器，新增SetReadDeadline，收到任意消息自动刷新 60s 存活时间；
