# Go\-Gin\-GORM 项目分层标准手册（Handler/Service/Repository）

## 前言

本手册为 **Go 后端通用企业级分层规范**，适用于所有 Gin\+GORM 业务项目（短视频、网盘、笔记系统、管理后台等全部通用）。

三层架构目的：

- **解耦**：http、业务逻辑、数据库操作完全隔离

- **可维护**：改接口不改数据库、改业务不动路由

- **可面试**：面试官最认可的标准工程结构

---

## 一、三层整体架构总览（最重要）

**固定单向数据流，绝对不允许反向调用**

前端请求 ➝ Handler ➝ Service ➝ Repository ➝ MySQL

返回数据 ➜ Handler ➜ 前端

**禁止规则：**

- ❌ Service 不能直接操作数据库

- ❌ Handler 不能写业务逻辑、不能操作数据库

- ❌ Repository 不能处理业务判断、不能读取 Request

- ❌ 三层禁止跨层乱跳（Handler 禁止直接调 Repository）

---

## 二、三层详细职责（100% 精准划分）

### 1\. Handler 层（控制器 / 路由层）

**定位：只负责网络、请求、响应**

对应文件夹：`/handler`

✅ **只做这 4 件事**：

- 接收前端参数（uri / query / json）

- 参数校验（validator）

- 调用 Service 层方法

- 统一返回 JSON 结果

❌ **绝对不能做**：

- 不写业务判断

- 不操作数据库（不出现 GORM 代码）

- 不写复杂逻辑

一句话：**Handler 是“传话员”，只收请求、返结果。**

---

### 2\. Service 层（业务逻辑层）

**定位：所有业务规则、判断、流程全部写这里**

对应文件夹：`/service`

✅ **只做这 3 件事**：

- 业务合法性判断（id不能为0、年龄合法、状态判断）

- 业务流程组装（先查、再改、再删、异步组合）

- 调用 Repository 获取/修改数据

❌ **绝对不能做**：

- 不接收 HTTP 请求（不操作 gin\.Context）

- 不直接操作数据库（不写 gorm 语句）

一句话：**Service 是“老板”，决定业务怎么做，但不碰数据库、不碰网络。**

---

### 3\. Repository 层（数据访问层）

**定位：只做数据库 CRUD，纯数据搬运**

对应文件夹：`/repository`

✅ **只做这 2 件事**：

- 封装 GORM 增删改查

- 返回数据 / 错误给 Service

❌ **绝对不能做**：

- 不做业务判断

- 不处理请求、不返回 JSON

- 不写复杂逻辑

一句话：**Repository 是“搬运工”，只负责读写数据库。**

---

## 三、配套固定文件夹职责（全套工程规范）

**所有项目统一这套目录，永远不乱建文件夹**

- **/model** 数据库结构体、表模型（只定义字段）

- **/config** 配置初始化（数据库、Redis、全局配置）

- **/handler** 路由接口层

- **/service** 业务逻辑层

- **/repository** 数据库操作层

- **/utils** 工具函数（JWT、加密、时间处理）

- **/middleware** Gin 中间件（跨域、鉴权、日志）

---

## 四、标准接口执行流程（逐行对应）

以「查询用户」为例：

1. **Handler**：获取 id、校验参数、调用 service\.GetUserInfo

2. **Service**：判断 id 合法性、调用 repo\.GetUserById

3. **Repository**：执行 gorm 查数据库、返回数据

4. **原路返回**：repo ➝ service ➝ handler ➝ 前端

---

## 五、三层代码写法硬性规范（面试必背）

### 1\. Handler 规范

- 函数必须接收 `*gin.Context`

- 不出现任何 gorm 语句

- 统一返回 `c.JSON`

- 参数绑定、参数校验只在这里写

### 2\. Service 规范

- **绝对不接收 gin\.Context**（只接收纯参数）

- 函数返回：\(数据, error\) 固定格式

- 所有业务判断全部写在这里

### 3\. Repository 规范

- 只操作数据库

- 函数参数简单、纯粹（uint、string、结构体）

- 不处理业务、不返回前端信息

---

## 六、新手最常犯的 5 个错误（全部禁止）

- ❌ Handler 直接写 GORM 查询（最严重、最土）

- ❌ Service 里面获取 ctx 参数、返回 JSON

- ❌ Repository 写业务判断

- ❌ 所有代码写在 main\.go

- ❌ 跨层调用（Handler 直接调 Repository）

---

## 七、合格的分层项目标准（你以后项目必须满足）

只要你的项目满足下面几条，就是**企业级规范、面试满分项目**：

- 三层职责绝对清晰、无乱代码

- 网络逻辑、业务逻辑、数据逻辑完全解耦

- 改数据库不影响业务、改业务不影响接口

- 所有 CRUD 严格遵守单向调用

---
