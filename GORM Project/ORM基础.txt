# ORM 完整概念与GORM前置学习文档
## 一、ORM 全称与直译
ORM = Object Relational Mapping
中文直译：对象 关系 映射
三部分拆分释义：
1. Object（对象）：编程语言里的结构体/类实例，Go语言中就是 struct 结构体变量
2. Relational（关系）：关系型数据库，主流：MySQL、PostgreSQL、SQLite、SQL Server
3. Mapping（映射）：建立代码对象 和 数据库表之间自动转换的规则

## 二、原生SQL写法 VS ORM写法对比
### 方式1：传统原生SQL（不用ORM）
需要手动拼接SQL语句，代码+SQL混合编写，繁琐易错
定义结构体映射表结构：
type User struct {
	ID   int64
	Name string
}
// 实例化数据
u1 := User{ID: 1, Name: "Tom"}
// 必须手写完整SQL插入语句，字段、值一一对应，容易写错字段名、逗号、引号
sql := "insert into user(id,name) values(1,'Tom')"
// 再调用数据库执行SQL，手动处理查询结果、映射到结构体

缺点：
1. 字段多时代码冗余，每张表增删改查都要重复写SQL
2. 手写SQL极易出现语法错误、SQL注入漏洞
3. 表结构修改后，所有相关SQL语句都要同步修改，维护成本高
4. 手动将数据库查询结果赋值给结构体，重复样板代码多

### 方式2：ORM框架写法（以GORM为例）
只写Go代码，框架内部自动生成并执行SQL，开发者无需手写SQL
type User struct {
	ID   int64
	Name string
}
u1 := User{ID: 1, Name: "Tom"}
// 一行代码完成插入，底层自动生成insert语句执行
db.Create(&u1)

## 三、ORM核心映射规则（Go结构体 ↔ MySQL数据表）
1. 数据库 数据表  ↔ Go 结构体（type User struct{}）
2. 数据库 单行数据  ↔ Go 结构体实例（u := User{}）
3. 数据库 列/字段  ↔ Go 结构体内部字段（ID、Name）
4. 数据库 多行数据  ↔ Go 结构体切片（var userList []User）

## 四、ORM 优缺点
### 优点
1. 大幅提升开发效率，不用重复编写基础CRUD的SQL语句
2. 自动防止SQL注入，框架内部做参数转义，安全性更高
3. 多数据库兼容，一套Go代码可无缝切换MySQL/SQLite等，不用修改SQL
4. 自带表自动迁移、分页、事务、预加载、软删除等通用功能
5. 代码可读性更好，纯Go逻辑，不用混合SQL字符串

### 缺点
1. 有少量性能损耗：框架内部反射、自动生成SQL，复杂查询比手写优化SQL慢一点
2. 复杂多表联查、统计聚合场景，ORM语法会很绕，灵活性不如原生SQL
3. 长期依赖ORM会弱化手写SQL能力，底层数据库原理理解变浅
4. 自动生成的SQL不一定最优，特殊业务场景需要手动原生SQL补充

## 五、GORM 框架简介（Go语言主流ORM）
1. 定位：Go生态最流行、文档完善的ORM库，专门操作关系型数据库
2. 支持数据库：MySQL、SQLite、PostgreSQL、SQL Server
3. 核心能力：
   - 自动表迁移（根据结构体自动创建/更新数据表）
   - 完整CRUD封装：创建、查询、更新、删除
   - 链式调用，条件查询、排序、分页、聚合函数
   - 事务、软删除、模型钩子、关联表（一对多/一对一）
   - 支持原生SQL混合使用，兼顾简单业务与复杂查询
4. 适用场景：绝大多数Go后端Web项目（搭配Gin使用）

## 六、补充使用建议
1. 简单单表增删改查：优先使用GORM封装方法，提升开发速度
2. 复杂统计、多表超大联查：使用GORM提供的原生SQL执行功能，手写优化SQL
3. 学习路线：先掌握ORM基础用法，再回头理解底层SQL原理，两者结合
